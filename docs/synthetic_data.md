# 模拟数据说明（synthetic）

> **声明：本文档描述的两张表均由本项目脚本生成，不是任何企业的真实数据，也不是真实 AI 产品的生产日志。**
> 它们只用于演示 A/B 实验检验与 AI 请求成本分析的方法。任何引用这两张表的结论都必须标注为模拟结果。

| 项目 | 内容 |
|---|---|
| 生成脚本 | `src/generate_ai_request_logs.py`、`src/generate_ab_test_data.py` |
| 输出位置 | `data/generated/`（已 gitignore，可由固定种子完整复现） |

## 1. `ai_request_logs.csv` —— AI 请求日志

### 用途

请求成功率、响应时间分布（P50/P95）、Token 消耗、按功能类别的估算成本、单位成功请求成本。
不用于：模型质量评测、模型路由、推理优化。

### 与原始数据的关系

- `account_id` 只从真实存在的 500 个组织客户中抽取（按席位数加权），因此可通过外键关联回 `raw_accounts`。
- `feature_name` 复用 `raw_feature_usage` 中已出现的通用功能名（`feature_1` 等），**不代表任何具体业务功能**。
- 日期范围 2023-01-01 ~ 2024-12-31，与原始数据一致。

### 生成逻辑

1. 按日生成请求量：基础量 40 次/日，随时间线性增长 55%，叠加工作日/周末系数（周一至周五 1.05~1.20，周六 0.70、周日 0.62）。
2. 每日请求量服从泊松分布。
3. `input_tokens` 取对数正态（median ≈ 3,000），`output_tokens` 取对数正态（median ≈ 665）。
4. `latency_ms` = 基础耗时（随 token 数上升）× 对数正态抖动（sigma = 0.35）。
5. `request_status`：基线成功率 98.5%，失败为 `error`；异常窗口内失败按 6:4 分为 `timeout` 与 `error`。
6. `estimated_cost` = 输入 token × 输入单价 + 输出 token × 输出单价，单价见 `config/ai_pricing.json`。

### 人为注入的异常窗口（用于验证异常检测方法）

| 编号 | 时间窗口 | 设定 | 目的 |
|---|---|---|---|
| E1 | 2024-08-12 ~ 2024-08-18 | 平台级故障：全部功能延迟 ×2.4，成功率降至约 82%，失败以超时为主 | 验证成功率与 P95 延迟的异常检测 |
| E2 | 2024-11-05 ~ 2024-11-09 | 请求量降至日常的 45% | 验证请求量类指标的异常检测 |

**为什么 E1 设为平台级**：原始数据中 40 个功能的使用量接近均匀（每个约 650 次），若只影响少数功能，信号会被稀释到无法检出。设为平台级后，维度拆解的结论应为"各功能同步受影响，指向平台层问题而非单一功能"。

### 固定参数

| 参数 | 值 |
|---|---|
| 随机种子 | 20240101 |
| 行数 | 37,490 |
| 整体成功率 | 98.34% |
| 估算成本合计 | 73.73 USD（模拟费率） |

### 模拟费率（`config/ai_pricing.json`）

- 输入 $0.30 / 百万 token，输出 $1.20 / 百万 token
- 该费率是项目设定值，**不代表任何厂商的真实计费标准，也不是真实账单**
- 修改费率后必须重新生成 CSV 并重跑分析

## 2. `ab_test_onboarding.csv` —— 新手引导实验

### 用途

演示一个完整 A/B 实验链路：业务假设 → 样本量估算 → SRM 检查 → 两比例检验 → 置信区间 → 护栏指标。

### 与原始数据的关系

`user_id` 是本实验的样本编号（`EXP-000001` 形式），**与 RavenStack 的 `account_id` / `subscription_id` 无关，不冒充真实成员 ID**。这是一份独立数据，不与主表关联。

### 实验设定

| 项目 | 值 |
|---|---|
| 目标指标 | 激活率 `activated` |
| 护栏指标 | 7 日留存 `retained_d7` |
| 随机分配单位 | 单个实验样本 |
| 基准激活率 | 30% |
| 最小可检测效应 | 相对提升 10%（即 33%） |
| 显著性水平 | alpha = 0.05（双侧） |
| 统计功效 | power = 0.8 |

### 样本量估算

使用 `statsmodels.stats.power.NormalIndPower` 与 `proportion_effectsize`：

- Cohen's h 效应量 = 0.0646
- 每组所需样本量 = **3,762**，两组共 **7,524**

样本量先算后生成，生成时严格按该数量分配，不额外增删。

### 生成参数

| 参数 | 值 |
|---|---|
| 随机种子 | 20240915 |
| 对照组真实激活率 | 0.30 |
| 实验组真实激活率 | 0.33 |
| 两组 7 日留存率 | 均 0.62（不设提升，用于观察护栏是否被伤害） |
| 分组时间范围 | 2024-09-01 ~ 2024-09-30 |

生成后的观测值（仅用于核对生成是否符合设定，**不作为实验结论**）：对照组 30.46%、实验组 34.16%。实验结论由 `src/ab_test_analysis.py` 重新检验得出。

## 3. 使用限制

1. 这两张表不能用于推断真实用户行为、真实成本或真实产品效果。
2. 估算成本是小 Token 量下的模拟值，不构成费用预测。
3. A/B 实验是单次模拟实验，结论不可外推到真实产品决策。
4. 运行 `python -m src.generate_ai_request_logs` 与 `python -m src.generate_ab_test_data` 可完整复现，结果与上述参数一致。
